# ADR 0001 — Develop GAIDE-Trace under the GAIDE harness

- **Status:** accepted
- **Date:** 2026-08-27
- **Decision-makers:** José Menezes

## Context

GAIDE-Trace was built through v0.3 with no governed layer of its own: no briefing for the agents that write most of its code, no constitution, no specs, no enforcement mechanism, no tests, no CI. Every rule that mattered — capture must never break the session, redaction happens at capture time, the capture path stays standard-library only, JSONL is the truth — lived either in prose in `docs/ARCHITECTURE.md` or in the head of the maintainer, and was re-explained to each agent session from scratch.

That is an awkward position for this project in particular. GAIDE-Trace's own thesis, inherited from [GAIDE](https://github.com/jcarlos78/GAIDE), is that **instructions degrade and mechanisms don't** — it exists because prompt history is not an auditable record. Governing itself by prompt history contradicted the product.

Two objections had to be answered first:

1. **Doesn't this create a dependency?** No. GAIDE-Trace remains a standalone, opt-in companion: nothing in the shipped artifacts (`hooks/`, `tools/`, `server/`, `schema/`, `install.sh`) references GAIDE, and the harness added here governs *this repository's development*, not its runtime. A user installing GAIDE-Trace into a non-GAIDE project is unaffected.
2. **Doesn't this contaminate the research?** The opposite: this repository's own sessions become traced data collected under a documented governance regime, which is the configuration the research is about. The self-tracing store stays local and gitignored (D3), like any other.

## Decision

Adopt the GAIDE template's harness into this repository, at the same level of completeness GAIDE ships, adapted to a dependency-free Python project:

1. **Portable layer, copied as-is:** `agents/skills/` (spec-writer, code-reviewer, security-reviewer, verifier, adr-writer, test-generator), `agents/reviewers/` (clean-context rubrics), `scripts/` (check-secrets, check-file, check-security, check-clean-state, sync-adapters), `specs/constitution.md` and `specs/template/`.
2. **Bindings, generated:** `.claude/` (briefing import, permissions, hook adapters, skills, reviewer subagents) and `.agents/` (Antigravity rules and workflows), regenerated by `scripts/sync-adapters.sh`, drift-checked in CI.
3. **Guaranteed floor:** `.pre-commit-config.yaml` and `.github/workflows/security.yml` — gitleaks, semgrep, osv-scanner, adapter drift — applying to every commit from any agent or human.
4. **Briefing adapted to this project:** `AGENTS.md` states the stack, the two distinct `hooks` layers (product code vs. governance binding), and promotes the architecture's design decisions to a **project-specific invariants** section (D4, D5, D6, D7, canonical vocabulary, opt-in default, stdlib-only).
5. **One invariant promoted from prose to mechanism:** `scripts/check-stdlib-only.sh` parses the imports of `hooks/`, `tools/`, `server/` and `schema/` and rejects anything outside the standard library. It runs on every Python edit (via `scripts/check-file.sh`, hence via the PostToolUse hook) and in `init.sh`. This is the invariant an agent is most likely to violate helpfully — reaching for `requests` or `jsonschema` — and the one whose violation is least visible in review.
6. **Real bring-up in `init.sh`:** interpreter floor, compile every module, stdlib-only check, event-schema validity, test suite, and a live health check that starts the server on a throwaway data dir and hits `/healthz`.
7. **No retroactive specs or tests.** Pre-GAIDE behavior is not back-filled wholesale; the first behavioral change to a component writes the spec and the tests for the behavior it touches (documented in `specs/README.md` and `tests/README.md`).
8. **Self-tracing as personal opt-in:** the maintainer's own hooks are registered in `.claude/settings.local.json` (gitignored), per D3 — contributors are not traced by cloning.

## Alternatives considered

- **Policy documents only (AGENTS.md + constitution, no hooks/CI):** cheapest, and precisely the failure mode both projects exist to refute — instructions with no mechanism behind them.
- **Retroactive specs for the whole v0.3 surface:** would produce specs derived from the implementation, documenting what the code does rather than constraining what it should do, while consuming the budget the first real spec needs.
- **`git submodule` on GAIDE instead of copying:** the template is meant to be adopted and adapted (`AGENTS.md`, `init.sh`, and `check-file.sh` here are all project-specific); a submodule would freeze the generic version and make local adaptation drift.
- **Waiting until the project has tests:** the harness is what makes the absence of tests visible and blocking; ordering it after tests postpones it indefinitely.

## Consequences

### Positive

- The invariants that keep captured research data trustworthy (D4–D7, redaction, stdlib-only) are now enforced by mechanisms an agent under context pressure cannot rationalize away.
- Any agent in any tool — Claude Code, Antigravity, or an `AGENTS.md` reader — gets the same briefing, the same procedures, and the same checks.
- The project practices what it argues: its own development is governed and recorded, not just other people's.
- Security scanning reaches a codebase that handles session data, API keys, and an internet-facing server, and previously had none.

### Negative (accepted costs)

- Ceremony on a solo research project: SDD gates, ADRs, and human approval slow down small changes.
- The absence of a test suite is now load-bearing — `check-clean-state.sh` and `init.sh` will keep it visible, and Principle 2 blocks behavioral changes that ship without tests.
- CI scanners may flag findings in existing code that predate the harness; Principle 10 forbids silencing them, so they become real work.
- Generated bindings must be kept in sync (`scripts/sync-adapters.sh`), and CI fails on drift.

### Neutral

- `docs/ARCHITECTURE.md` keeps decisions `D1`–`D8` in their existing numbering as the project's founding record; new architectural decisions become ADRs from here.
- `.mcp.json` carries a single server (`playwright`), used by the `verifier` skill against the server console — this project integrates with nothing else by design.

## Constitution adherence

Establishes the constitution for this repository, so adherence begins here. The change is a single concern (Principle 7) and introduces no secrets (Principle 6). Principles 1 and 2 apply to work *after* this ADR, with the pre-GAIDE debt stated openly rather than papered over — no spec or test is fabricated retroactively to make the repository look compliant (the spirit of Principle 9).

## Future review

Revisit when: (a) the project gains contributors, at which point self-tracing and HIC mode deserve a team-level decision; (b) the test suite exists and the pre-GAIDE debt is materially paid down; (c) GAIDE itself changes the harness in a way worth re-adopting; (d) a new model generation makes parts of this scaffolding unnecessary (constitution's harness-expiry note).
